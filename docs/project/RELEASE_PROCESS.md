# Release Process

## Versionen

- Methodik: semantische Arbeitsversion `0.x`
- Softwarepaket: später eigener SemVer-Lifecycle
- Source-/Framework-Versionen werden unabhängig gespeichert

## Release-Artefakte

- Methodenmodell oder maschinenlesbarer Export
- Changelog
- Decision-/ADR-Änderungen
- Tests
- bekannte Einschränkungen

## Keine stillen Framework-Upgrades

Eine neue C5-, C3A-, EU-CSF-, NIS2-/DORA- oder Provider-Version löst ein Mapping-/Drift-Review aus. Alte Assessments werden nicht rückwirkend still neu interpretiert.
